环境同前：Windows 11 / Python 3.12.10 / torch 2.4.1+cpu。

## 2025-11-28 19:10 初始化尺度对梯度的影响

```bash
python code/01_mlp_scratch.py
```

先只看第一步：

```text
=== 初始化尺度 vs 第一步梯度范数 ===
Xavier     初始 loss 0.6931  梯度范数 2.14
std=0.5    初始 loss 0.6931  梯度范数 18.76
std=1.0    初始 loss 0.6931  梯度范数 1204.35
```

初始 loss 都是 0.6931 = ln 2，符合预期（两类、初始化输出接近 0），
但梯度范数差了三个数量级。std=1.0 时第一步的梯度范数是 Xavier 的 560 倍，
按 lr=0.1 走一步，参数直接被甩到很远的地方。

`std=0.5` 这个数字很有意思：$n_{in}=2$ 时 Xavier 给的标准差是
$\sqrt{2/(2+16)} = 0.333$，0.5 是它的 1.5 倍，梯度范数就大了 8.8 倍。
说明这个任务的梯度对初始化相当敏感。

## 2025-11-28 19:20 std=1.0 到底会不会崩

把 `train` 里的 init 换成 `std=1.0` 跑 30 个 epoch：

```text
epoch  1  loss 2.4131  acc 0.600
epoch  2  loss nan     acc 0.515
```

第 2 个 epoch 就 nan。这印证了 4.7 的分析：方差在层间被放大 $n_{in}\sigma^2 = 2$
倍，两层就是 4 倍，再乘上 200 个样本的累积，直接溢出。
**结论：初始化不是「随便给个小随机数」就行，Xavier 的系数是必需的。**

## 2025-11-28 10:30 权重衰减（第一版，bias 也被衰减）

```bash
python code/02_weight_decay.py     # 第一版：SGD(net.parameters(), weight_decay=wd)
```

```text
训练集 20 个点，测试集 100 个点，特征维度 21，参数量 22
  weight_decay  train_loss  test_loss       gap
         0e+00      0.0029     0.1843    0.1814
         1e-04      0.0036     0.0912    0.0876
         1e-02      0.0421     0.0489    0.0068
         1e-01      0.1204     0.1247    0.0043
```

看起来「衰减越强 gap 越小」，很符合教科书。但**两个损失都变大了**：
1e-2 时 train 从 0.0029 涨到 0.0421，1e-1 时直接 0.12，这已经是欠拟合了。

当时我的判断是「正则就是拿偏差换方差，正常」。后来发现一个问题：
偏差项 $b$ 也被衰减了。真实函数是 $y = 5 + 1.2x - \dots$，均值是 5 左右，
把 bias 压向 0 等于硬逼着模型穿过原点，当然拟合不好。

## 2025-11-28 13:50 改成只衰减 weight

用参数组把 weight 和 bias 分开：

```python
trainer = torch.optim.SGD([
    {"params": [net[0].weight], "weight_decay": weight_decay},
    {"params": [net[0].bias],   "weight_decay": 0.0},
], lr=lr)
```

重跑：

```text
  weight_decay  train_loss  test_loss       gap
         0e+00      0.0029     0.1843    0.1814
         1e-04      0.0033     0.0091    0.0058
         1e-02      0.0046     0.0062    0.0016
         1e-01      0.0117     0.0128    0.0011
```

对比第一版，1e-2 这一行的 test_loss 从 0.0489 降到 0.0062，**好了 8 倍**，
train_loss 也从 0.0421 回到 0.0046。所以「只衰减 weight」不是玄学细节，
它直接决定了正则是在帮忙还是在捣乱。

不衰减时权重 L2 范数是 41.7，1e-2 时降到 3.6。

## 2025-11-28 21:15 dropout：加了反而更差

```bash
python code/03_dropout.py     # 第一版：训练置零但不缩放
```

```text
 dropout  train_loss  train_acc  val_loss  val_acc
     0.0      0.0198      1.000    0.2413    0.870
     0.2      0.0481      0.981    0.3702    0.845
     0.5      0.0773      0.950    0.6124    0.830
```

dropout 越强，验证损失越差。我先怀疑是「这个任务用不着 dropout」，
但 p=0.5 时 val_acc 只掉到 0.83 而 train_acc 还有 0.95，说明训练是有效的，
问题出在训练和推理的不一致上。

打印隐藏层激活均值：

```text
同一批隐藏层激活在两种模式下的均值:
  训练模式: 0.1732
  推理模式: 0.3421
```

推理是训练的 1.97 倍，正好是 $1/(1-0.5)$。**根因找到了**：
训练时置零让期望缩了一半，推理时没缩，两层叠加放大约 4 倍，
后面的 logits 尺度不对，交叉熵自然大。

按 4.6 的 inverted dropout 改：训练时除以 $(1-p)$，推理时原样。改完再跑：

```text
 dropout  train_loss  train_acc  val_loss  val_acc
     0.0      0.0198      1.000    0.2413    0.870
     0.2      0.0261      0.995    0.1954    0.885
     0.5      0.0589      0.960    0.1723    0.905
```

p=0.5 时 val_acc 从 0.870 升到 0.905，**第一次看到 dropout 是真的有效**。
train_loss 从 0.0198 涨到 0.0589 是应该的——正则本来就会牺牲训练误差。
